# Glossary

What each word means here, one line each. **Definitions only** — the rules that govern
any of it are in the skill `CLAUDE.md` routes you to, and the file named beside a term is
where its type lives.

Where a word is ordinary English used narrowly, the narrowing is the definition.

## The unit of work

`src/workflow/domain/trak.ts`

| | |
|---|---|
| **trak** | one piece of work: a description, a plan, a worktree, a branch, and an append-only log of events |
| **description** | the request in the words it was asked in, set once at creation |
| **intent** | the description **plus every decision recorded since** — what the composer and every later agent read, rather than the original request |
| **host repository** | the checkout you ran `ork` in. A trak's worktree is elsewhere; a merge goes to the branch the host is standing on |
| **worktree** | the checkout a trak works in — every turn and every check runs there. Under a runner a host provides it is in the trak's sandbox at the same path, the engine host has no checkout there, and its branch reaches the host only by fetch — `src/vcs/ports/sandboxes.ts` — except for a trak its starting agent's `place: host` keeps on the engine's machine — `src/vcs/ports/host-traks.ts` |
| **expose** | `runner.sh expose <trak> <port>`: `<port>` in the trak's sandbox on `127.0.0.1` or else `::1`, reached at the same port on the engine host, for as long as the engine holds it — a declared process's run, under a runner file — `src/vcs/ports/sandboxes.ts` |
| **reach** | the reverse of **expose**: the engine host's `127.0.0.1:<port>` reached from inside the sandbox — the engine's own port, held for each turn so its session can dial the engine's MCP routes, behind a relay in the sandbox that keeps accepting while the engine is down |
| **base** | the branch a trak's branch starts from. Absent means the host's `HEAD`; a child is handed its parent's branch |
| **slice** | which of a trak's changes to read: the whole branch, one step's commit, or what is in the checkout and not yet committed. A committed slice outlives the checkout; the uncommitted one is the only one that needs it — `src/vcs/types/worktree.ts` |
| **run mode** | how much of a trak its person stands at: `manual` (every gate) · `smart` (a gate goes past unless the turn behind it reported **ambiguity** at or above the threshold, the record shows the person was already there — a second turn at that position, work raised that nobody planned, or a round of fixing that repeats itself or is the fifth — or the composer wrote a **hand-off**, where approving opens traks outside this one — never on a **goal**'s trak — or proposed a goal on its finish) · `auto` (the plan and each artifact taken for them, questions answered by taking the option the agent recommended and leaving the rest to its own judgement, and a conversation ended by telling it to carry on; a failing check and a step that gave up still park) · `decider` (the plan and each artifact taken as on `auto`, but questions and conversations always park for the person, and a plan carrying a **hand-off**, or a finish proposing a goal, stops at its gate). On every mode, an artifact filed by an entry planned as a conversation waits for the person. A spawn's **child** ends itself by it too — `auto` and `decider` any child, merged where something was committed and archived where not; `smart` only one with nothing on its branch; `manual` never, and no trak at the top on any mode but a goal's, which ends itself on every mode where nothing was committed. All four are decided in `attention.ts`, the one file that reads it. Set at creation, inherited by a spawn's children, and changed any time after with `ModeChanged` — picked up at the next gate, with the turn in flight left to finish |
| **hold** | a one-shot press to hold the step that is running or gated until the person accepts it, whatever its **run mode** would do at its gates; a spawn has no gate and is passed over. `Trak.holding`, set by `HoldChanged` (never on `manual`), spent as that step is accepted — the entry stamped on `Trak.marks` as `Held` — or as the trak comes to rest (a child with one pending holds at `Finished` rather than ending itself), and cleared by a change to `manual`; read in `attention.ts` beside the mode. Not custody — `Runs.holder` is a different thing under a neighbouring word |
| **skip checks** | the **hold**'s twin with the opposite promise: a one-shot press so the trak's next check run does not happen and the step is accepted exactly as a pass accepts it — on `auto`, with nobody reading it. `Trak.skippingChecks`, set by `SkipChecksChanged` on any mode, honoured in the runtime's `RunChecks` handler — the one place the check list is read — and spent by the `ChecksPassed` that names what it `skipped`; a run with nothing to skip leaves it armed. Always written with its noun: a bare **skip** is the gate action that enters the next step with nothing filed |
| **waiting message** | what a person sent while the trak was being driven and no agent has read yet: `Trak.messages`, added by `MessageWaiting`. It leaves one of four ways — the running turn reads it (`MessageDelivered`), the next turn that starts reads it, it is the chat at the gate the trak parks at, or a stop or an ending hands it back unsent on `Trak.returned` |
| **stop** | ending the turn in flight — `POST /stop` at `AgentWorking`, or at `Composing` with a plan. `StopRequested` puts the trak in `Stopping` before anything is killed, `StopTurn` kills, and `Stopped` parks it at the step's conversation gate or the plan gate, holding the session the turn had or was about to resume |
| **cancel** | ending the check that is running, from the same press that stops a turn — `POST /stop` at `CheckRunning`. The drive is taken over, the script's process group dies, and `ChecksCancelled` is the run's only ending: no strike, no agent turn, and the trak parks at the `checks` gate a failing run opens. Neither one-shot nor the cancel reaches an agent's **effects** |
| **record** | how a trak went: computed from its log, never accumulated as it runs. Written out as markdown when the trak merges — `src/workflow/domain/record.ts` |
| **projection** | `.orkestra/.trak/`: the trak as files a turn can open — `trak.md`, every document filed before the running step, and a spawned child's inherited ones under `from-parent/`. Rebuilt from the log and replaced outright before every turn, so each file is what that turn filed when it ran and an edit to one does not survive — `src/workflow/domain/projection.ts` |
| **goal** | a finished state a person approves as its **goal file**, and the composer that reaches it by opening the traks it is confident in, waiting for each to land and adding more — a second object beside the trak with its own log, and no worktree or checks, and no branch unless its **goal file** names one or, for a sub-goal, its parent has one. `.orkestra/GOALS.md`, where a project keeps one, is handed to its composer as this project's rules for goals. Every move it makes is a tool call on an MCP server only its session is handed; it stops for a person at its drafted **goal file**, an escalation, a request for work by hand and done — never before it opens traks, which it does with nobody asked, keeping the likely next few as its plan with `replan` —  and any number run per project at once, each with its own composer turns. A top-level trak outside any goal may start one: its composer proposes it as `goal` on its finish, and once the trak has finished the engine starts it with every document the trak filed, stopping at its drafted goal file. A **sub-goal** is a goal its parent's composer opened with `open_subgoal` from an entry `replan` put in the plan — a title, a line and a finished state — so it has no goal file and opens its own traks on its first turn. It opens traks and never goals; its gates stop for the person, and its parent's composer is woken only when it is done, dropped or stuck, sees how many of its traks opened, landed and are running on every turn, and may wake its composer with `message_subgoal` — refused while it stands at a gate — or drop it with `drop_subgoal`, which wakes nobody and takes it off the plan. Pausing or dropping the parent pauses or drops it — `src/workflow/domain/goal.ts` |
| **goal file** | a goal's spec in the shape of a file, though never written to one: a title and a `line:` in frontmatter, the finished state as the body, and optional `parallel:`, `traks_per_hour:`, `traks_per_day:` and `modes:` limits the engine holds the composer to, `auto_merge: false`, which refuses a trak that merges itself, and `branch:`, the **goal branch**: made on `origin` from the default branch when the goal starts, every trak of the goal cut from it and landing on it — its pull request aimed there through `ORKESTRA_TARGET_BRANCH`, its Merge press merging into the engine's own checkout of it, `.orkestra/.worktrees/goal-<id>`, and pushing — and opened as one pull request into the default branch at Confirm done, which a person merges. Its composer keeps it current with `merge_default_branch`, which merges `origin`'s default branch into it and never the other way: a clean merge is pushed inside the call, and a conflict changes nothing and is resolved by a trak the composer opens. A drafted file may propose one, and the person keeps, changes or clears it on the gate card. Drafted by the composer from a sentence — after scoping questions where the sentence leaves the scope open, and opening with the scope it assumed and what it left out — under a `name` no other goal in the store holds. Approving it appends it to the goal's log as its spec, the only copy: approval writes no file and commits and pushes nothing, under any store, and only a goal branch it names reaches `origin`. A **sub-goal**'s branch is its parent's goal branch with `-<id>` appended, cut from it and merged into it at the sub-goal's Confirm done, with no pull request; under a parent with none, a sub-goal has none. A sub-goal's limits are its parent's, tightened by any set on it: its own `parallel:`, `traks_per_hour:` and `traks_per_day:` count its own traks, and the parent's count its own traks and every sub-goal's. — `src/library/logic/goal-file.ts` |
| **corpus** | `.orkestra/records/`: a folder per trak whose checkout is gone — `Merged`, `Closed` or `Abandoned`, never `Finished`, which still holds one — under the day it merged or, failing that, ended, each holding its record and every document it filed. Gitignored, rebuilt from the logs by `pnpm ork records` — `src/app/records.ts` |

## The plan

`src/workflow/domain/outputs/proposal.ts`

| | |
|---|---|
| **composer** | the agent that proposes the sequence. **A step like any other**: each of its runs is an entry in the plan, with a position and a session |
| **proposal** (a **plan**) | a title, an ordered non-empty list of steps, and optionally a rationale |
| **step** (a **plan entry**) | one entry: a compose, an agent turn, or a spawn. A **proposed step** is the same three, and a proposed compose carries an instruction where the engine's carries a `why` |
| **position** (**step index**) | zero-based index into the plan. A step's identity — not its agent's name |
| **slot** | what the trak has accumulated at one position: the session, the attempts, the skip, the children, the failing checks. **Never dropped** — nothing that ran is replaced, so nothing needs truncating |
| **instruction** | the composer's contribution to one entry: what this particular step is for |
| **rationale** | what the composer found that shaped the sequence. Absent is the ordinary case |
| **stops short** | a plan whose last entry is a **compose** — the composer saying *ask me again once this has run*, with what it could not see past as that entry's instruction |
| **`Finished`** | the virtual step at index N — never declared, always reachable |
| **resume point** | the position approving a plan enters at: the first entry that has not run |
| **splice** | how a revision lands — the run fills in the **ask** it was made for, the unrun tail behind it is truncated, and the remainder follows. **Nothing that ran is moved, replaced or renumbered** |
| **reconsult** | the composer is owed a turn. Four things feed it: a step **raised** something — as does a child's **hand-up**, which arrives at the join as one — a person **replanned**, the world came back (**reentered** naming no agent — one that names an agent splices that turn into the plan and owes the composer nothing), or a merge **conflicted**. A plan that **stops short** is not one of them — that is an entry the plan reaches, not a fact carried on the trak |
| **ask** | the compose entry the engine writes at the join the moment a reconsult is made, carrying its `why`. It is the entry that run lands on — and it goes again if the reason does, which is a person arguing away what an artifact raised |

## What a human declares once — `.orkestra/`

`src/library/types/agent.ts`, `src/library/types/check.ts`

| | |
|---|---|
| **agent** | a named role: a file under `src/library/shipped/agents/`, `.orkestra/agents/` or `.orkestra/.local/agents/`, the later layered over the earlier field by field — plus `generic`, the role-less one the **engine** ships as `src/library/shipped/generic.md`, held beside the fleet rather than in it so nothing the composer reads can see it. Holds the model, the effort, the permission, the output sections, the checks, the effects, the repository skills it reads, whether it is startable, and the brief. A plan entry names **one**, and nothing else about the step is on the entry |
| **startable** | `start: true` in the agent file — this role can be the **first** thing that happens in a trak, with no plan and no prior step behind it. What New Trak's shelf offers and what the create route guards on, off a `start` field `GET /api/agents` carries on every agent it sends. `generic` is one, reached from New Chat as well as the shelf. `resolve` and `unblock` are not: one needs a merge that did not go in, the other a step that reported it was stuck |
| **brief** | the agent file's body: that role's anti-instincts. The repository skills it reads are its `skills:`, named with their paths on the session |
| **opening** | the one flag a brief may test, as `{{#opening}}…{{/opening}}` or `{{^opening}}…{{/opening}}`: true on the entry a trak was opened with — New Chat, or New Trak with an agent named — and false on an Ask, a composed plan's steps and a spawned child's. Any other tag in a body refuses the file at load — `BRIEF_FLAGS` in `src/library/types/agent.ts` |
| **section** | one title an artifact from that agent must (or may) contain. A `may` one carries the fact that makes it due — the loader refuses one without |
| **figure** | a section, or part of one, written as a fenced block labelled with a figure's name — `decision`, `overview`, `walkthrough` — which the client draws and the next agent reads as written. A section asks for one with `figure:`; a fence that does not parse draws as its source |
| **check** | a named script under `.orkestra/checks/`, or one the engine ships under `src/library/shipped/checks/` that a project script of its name replaces, declared by an agent, run against the worktree after the artifact and before a human sees it. Non-zero means **the work is wrong**, and sends the step back to fix it. An agent can run any one with `cache` on during its turn through the `run_check` MCP tool, its own or not, and a pass that keeps is the one the engine reuses |
| **print**                   | what one test file's pass on one content depended on — up to ten per file, the least recently used dropped first — for a check with `fingerprint:`: every file it read — a file in pnpm's store as its nearest lockfile, which makes the print lean on `lockfile` — every script V8 ran with the bodies of the functions it never called, a barrel of named re-exports with the names and blocks it may gain, the binary of every sealed tool it spawned, with `git --exec-path`'s helpers beside `git`'s, and every native addon its process loaded, with the assumptions its recording leaned on. Kept under the label, the sealed tools, the recording format (`RECORDING_FORMAT`, raised whenever the hook grows stricter), the OS and the architecture with no tree, and a unit whose print the checkout still agrees with, and whose assumptions the machine trusts, is skipped but never proven — `Passes.printed`, `src/recording/`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **assumption**              | a doubt about a test file's recording that a trusting machine accepts rather than run the file: `gitconfig`, `lockfile`, `ps` or `tmpdir`, named by the recording. An engine trusts unless `CI` is set, and then accepts the **floor** alone — the clock, the environment and randomness do not matter, Node is its binary, the kernel and libc stay the same — which every machine accepts and nothing names — `ASSUMPTIONS`, `src/recording/types/recording.ts`; `trustsOn`, `src/recording/logic/trust.ts`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **unit proof** | one line a check with `units: <label>` appended to `ORKESTRA_UNITS_OUT` — a unit it proved, opaque to the engine unless the check has `fingerprint:` — kept under the tree, the label and the platform part, and handed to the next check with that label on the same files as `ORKESTRA_UNITS_PROVEN` — `Passes.unitKeyOf` |
| **stage runner** | `src/check-stages.ts`, whose path every check is handed as `ORKESTRA_STAGES`: it resolves each `pnpm [--filter <pkg> \| -r] <script>` it is given through `package.json`, a chain part by part, runs a script starting with `vitest` as a test stage and any other command as written, leaves out the files `ORKESTRA_UNITS_PROVEN` names, appends each passing one to `ORKESTRA_UNITS_OUT`, and under `fingerprint:` lists the recording setup file in each resolved project's `setupFiles` and `server.fs.allow`, so a project's config names none — `CHECK_STAGES`, `src/app/packaged.ts` |
| **env script** | `.orkestra/worktrees/env.sh`: sourced by the engine in a spawn's own directory before every agent turn, check, effect, `setup.sh` and `teardown.sh`, with what it left exported laid over that spawn's environment — `Library.env`. Never cached, never before the engine's own `git` and `gh`; a script that fails or times out fails the spawn, with its stderr |
| **effect** | the same registry of scripts, named under an agent's `effects:` instead, and run once that step's work is on the branch — after the gate, so the approval is what authorised it. It **acts** rather than judges, outside this checkout, so non-zero means **it could not do it** and stops the trak at `Failed{project}`. Written to be idempotent, because a restart re-issues it. A person may **skip** a failed one instead of retrying it — `POST /api/traks/:id/skip-effects`: the step is entered as a pass enters it, and neither the failed effect nor any declared after it runs. `EffectsRan.skipped` names each, and is the note the step carries |
| **condition** | the same registry again, named under an agent's `conditions:`, and asked **before a step of that agent starts**. It asks about the world — a pull request merged, a deploy landed — so its exit has three meanings, this list's alone: `0` the step runs, `1` *not yet*, and anything else **gives up** — the engine stops asking and a push says so; a script that timed out or could not start is not yet. Not yet rests the trak at `Finished` holding the entry and every door a finished trak has, plus one of its own — `POST /api/traks/:id/run-now` — *Skip the wait* on the held block, or on the deploy block where the wait is the deploy's — which starts the held step with the wait unmet, on any kind of wait, after asking `merged` once more; `WaitSkipped` on the log, and the step's first prompt names the condition it was waiting on — and the daemon asks again on the interval the script's own `asked_every_seconds:` declares — the whole of the scheduling policy. Two names the engine answers itself, with no script behind them: **`merged`** — the branch has gone in, by the forge's listing or a merge made here — and **`deployed`** — `merged`, then `.orkestra/deploy.sh` run from the project root with the merge commit as `$1`, on the interval its header declares or the engine's own minute. Either may also sit on one agent plan entry as its `wait_for`, which the composer writes, asked after the entry's **time wait** and before its agent's conditions, a name the agent repeats asked once, and dropped at the plan gate by `ClearWait`. Either passing puts `Trak.landed` on the trak. The held entry is the slot's `waiting`, read through `waitingAt` — `src/workflow/domain/trak.ts`; the sweep is `src/app/conditions.ts` |
| **time wait** | `wait_until` on an agent plan entry — an hour on the local clock, `2026-09-16T06`, or an ISO-8601 duration, `PT90M` — asked before the agent's own conditions as a wait like theirs, recorded under the name `wait_until`, which no script may take. Both spellings resolve against **`Trak.planAt`**, the `at` on the newest event carrying a proposal, through `waitUntilAt` — never stored, never carried on the not-yet. The sweep wakes it on the instant rather than on an interval, and it never gives up. Crosses as `AgentStepDto.waitUntil` on a proposal and a plan's unrun tail, and as `WaitingDto.until` — `src/workflow/domain/wait-until.ts` |
| **landed** | `Trak.landed`: the branch went in while a `merged` or `deployed` wait was pending, and the commit it landed as — a merged pull request's merge commit, or the tip a local **Merge** left, which on such a trak keeps the checkout and asks the wait again rather than ending it. From then on no `permission: write` agent runs on the trak: refused at decode (`ComposerOutputFor`) and at the step, except the engine's own agent asked a question through re-entry, which runs read-only instead — `writesRefused` in `src/workflow/runtime.ts`, which holds a spawn child to its parent's landing too, read off the parent's log at the moment of refusal. A writer accepted into a child's plan before the parent landed is refused as its step starts, with `StepRefused` sending the child back to its composer. And a child merged into a landed parent never brings code: when the parent's branch does not already hold the child's tip, whichever turn or commit moved it, `MergeWork` drops the changes whole — `ChangesDropped` on the log, the child ending `Closed` — while its documents, requirements and hand-up reach the parent as they always do, by the **landing** or by the `ChildRefiled` a child sent back after it landed comes home as; a tip the parent already holds merges as before. Archiving a landed trak ends it `Merged`. Never set by a merge with no wait — that trak ends `Merged` and is not run on afterwards |
| **deploy script** | `.orkestra/deploy.sh`: what answers `deployed`, and what `GET /api/traks/:id/deploy` runs while a merged trak's page is open — one run shared across every tab, an answer reused for thirty seconds. Its presence is what lets an agent list `deployed` — `Library.deploy`, `src/app/deploys.ts` |
| **hosted process** | a long-running script under `.orkestra/processes/` — a dev server, a gallery — kept up in one trak's checkout, or in the project checkout, on a port the engine assigns. A trak's checkout can declare its own, seen at that trak alone. Started by a press (on a trak's side panel, or on the git bar for the project checkout), before a turn of an agent whose `processes:` lists it, by a turn through the process tools on its `orkestra-trak` server, or by a process whose `needs:` names it; never restarted on its own, and never a move of the trak. Daemon memory, not the log — `src/library/types/process.ts` |
| **permission** | `read-only` or `write` — what an agent may do to its checkout. A `write` step runs `claude` under `--permission-mode auto`, everything else under `bypassPermissions` |
| **permission request** | a step's `permission` envelope: one command the CLI refused, by its exact text, and why the step needs it. Parks at a `permission` gate on every run mode; **Allow** resumes the step told `Yes, you can run \`<command>\``, **Refuse** resumes it told not to |
| **effort** | the reasoning effort a turn runs at — `effort:` on a `models.yaml` entry, or on an agent file for turns on its own `model:`. One of the CLI's own levels, checked at load because the CLI warns and runs anyway on one it does not know; declared nowhere means no flag and the CLI's default |
| **policy** vs **mechanism** | policy is *what an agent is told* and lives in `.orkestra/`, over the fleet the engine ships in `src/library/shipped/`; mechanism is *how a turn is framed* and lives in `src/prompts/templates/` |
| **local overlay** | `.orkestra/.local/`: the same layout again, one person's, kept out of git by the engine and merged over the team's at load — `src/library/logic/overlay.ts`. An agent file layers over the team's field by field and a check replaces the team's of its name, each **shadow** logged at boot; `fleet.yaml`, `ORKESTRA.md`, `COMPOSITION.md`, `GOALS.md`, `deploy.sh`, `store.sh`, `worktrees/setup.sh`, `worktrees/teardown.sh` and `worktrees/env.sh` replaced outright; `models.yaml` laying its `models:` over the team's, overriding `default:` and laying its `context_windows:` over the team's model by model |

## One turn

`src/workflow/domain/trigger.ts`, `src/agent/interactions/elicit.ts`

| | |
|---|---|
| **turn** | one ask of one step, and normally one `claude` invocation. A **re-ask** is the exception — see below |
| **session** | the provider session id for a step, recorded in the log so a later iteration resumes the same conversation rather than starting one. The id the CLI announced: the one the runtime minted where the CLI takes one (`claude`), the CLI's own where it mints its own (`codex`) |
| **provider** | one coding-agent CLI the engine can spawn — `claude` or `codex` — as a bundle of three files under `src/agent/providers/`; the **registry** holds every one, and a turn's model name picks one by its `<provider>/` qualifier, a bare name picking the first — `src/agent/ports/provider.ts` |
| **standing brief** | the rules that hold for every turn of a session, in two halves: the **core** every role shares and the role's own output **contract**. On the session's system prompt under Claude; in the body of the opening turn under Codex, the contract again when a turn takes over another position's conversation — `src/agent/types/session.ts` |
| **trigger** | why an iteration is happening, and which resume prompt it gets: `Initial`, `Message`, `Answers`, `Unanswered`, `Unread`, `Filing`, `Reconsulted`, `CheckFailure`, `Interrupted`. The two `Un-` ones are what an unattended trak says in place of a person — nobody will answer, nobody will reply; `Filing` is a person asking for the document instead of saying anything |
| **elicit** | hold a turn to a schema-valid output, re-prompting on a malformed one or one its `vet` refuses — a step artifact with a mermaid block that does not parse |
| **re-ask** | one of those re-prompts. It resumes the session and so spawns a second `claude`, but it is the same ask: the whole loop is one turn and files one `AgentReturned`. The `Reask` transcript entry is what says so |
| **converse** | the other half — a turn whose reply a human is waiting to read, so prose is the point rather than a decode failure, and the reply is every result the turn wrote, joined in order — more than one where the agent wrote while **background work** ran; only an envelope that was meant as one and refused is re-prompted, and after three of those the last text is the reply |
| **transcript** | the append-only list of what a trak's agents did, one **entry** per normalized provider event — tier 2 of the store |
| **transcript entry** | one such line: `Spawned`, `Reask`, `Session`, `Tool`, `Text`, `Said`, `Subagent`, `SubagentResult`, `Background`, `BackgroundStarted`, `ApiRetry`, `View`, `Check`, `Hook`, or a `Note` carrying the text `eventLine` writes. Each carries the position its turn ran for, `"composer"` for a compose turn, and nothing at all on a line written before the engine stamped one; each also carries `at`, the epoch-millisecond time it was appended, which is what a duration is measured between — `src/agent/types/transcript-entry.ts` |
| **view** | the HTML an MCP tool declares for its result, drawn in the transcript where the tool was called. The engine reads it through the CLI and keeps it with the call's arguments and result when the call completes — `views/<call>.json` beside the transcript — and a `View` transcript entry names it. A **press** in one calls a tool on the view's own server through a CLI, with no model turn |
| **delegation** | one agent handing work to a subagent. `Subagent` is its head and `SubagentResult` its answer, both naming the `call` that asked; every line the subagent writes carries that id as its `parent`, which is the only thing two subagents running at once can be told apart by |
| **level** | a frame stating the full set of something as it stands, replacing the last statement rather than adding to it — the provider's `background_tasks_changed` is one, stored as the `Background` entry on each change of set |
| **background work** | a task the agent left running when it answered — a backgrounded shell command or delegation, named by the **level**. A result holding the step's envelope ends the turn at once: the engine stops what is still running, records it on the event that files the turn, and names it in the next prompt that session is sent. Any other result leaves the turn open while any is outstanding: it ends when the set empties, or when a person stops what is left from the step's own screen, and every result written before then is part of the answer |
| **activity** | what a tool call *did*, as a closed set named where Claude and OpenCode agree — `Bash`, `Read`, `Edit`, `Write`, `Grep`, `Glob`, `WebSearch`, `WebFetch`, `Todo`, `Task`, `Other`. The tool's own name rides beside it |
| **detail** | the one value an activity is worth showing with: a path, a command, a pattern. Absent for `Todo` and most of `Other` |
| **spend** | what a turn's model calls consumed, **added** over every report the provider made during it — uncached input, cache reads, cache writes, output, and money. Added again over a step's turns, a session's and a trak's. Never a measure of how full a window is: one turn's already comes to several windows' worth, because every model call re-reads the conversation — `Usage` in `src/agent/types/usage.ts` |
| **estimate** | what the turn in flight has spent so far as its readings say: each model call's **context occupancy** added once, laid over the provider's own report and replaced by the next one — Claude reports its spend only on the line that ends the turn, so until then this is the only figure that grows. On the run record and on the wire (`TurnInFlightDto`), never on the log — `Estimate` in `src/agent/types/usage.ts`, kept beside `Usage` in `meter.ts` |
| **context occupancy** | how much of the model's context window the conversation filled, as **one reading** rather than a sum: the whole input side and that call's output, at the turn's last model call. `Usage.context`, absent where the provider reported nothing per call. Its output count is short by the rest of the last reply where the provider writes the call as it starts, which Claude does; the input side is whole |
| **context window** | how many tokens a model's context holds. Three rungs, taken in order: what the CLI itself reported for the turn (`Usage.contextWindow`), then `context_windows:` in `models.yaml`, then no known window — which a surface draws as no ceiling rather than a guess |

## What a turn comes back with

`src/workflow/domain/outputs/`

| | |
|---|---|
| **artifact** | a step's primary output: its sections, and optionally requirements and corrections |
| **document** | what was filed, without the envelope that carried it. `Trak.artifacts` holds these |
| **artifact key** | what a document is filed under — position then agent, `2-build`. A spawn's child is a directory named the same way, `2.0-review`, and every document it filed is in it under the child's own key — `2.0-review/0-review`, a piece of one step included |
| **requirement** | something a turn settled about the finished work. Accumulates onto the trak and **outlives the document that carried it**. Called `decisions` inside the engine, where the name is pinned by every stored log |
| **kind** | which of four a requirement is — `out_of_scope`, `unplanned_work`, `constraint`, `ruled_out`. Only `unplanned_work` sends the plan back to the composer; the other three are recorded and cost nothing. Absent reads as not-`unplanned_work` — `isUnplanned` in `outputs/decided.ts`. Spent when it routes, so the trak's accumulated list carries none |
| **requirement id** | what every later entry names a recorded requirement by — its artifact key and its ordinal among that step's, `3-scope.2`. Derived from the list's order, never written — `identified` in `outputs/decided.ts` — and stable because a re-run step's list is unioned in rather than appended, `accumulated` |
| **supersedes** | the optional list on a requirement of what it replaces, beside any kind: a document key, and the projection writes the entry's text above that document's first section rather than editing it; or a requirement id, and every rendered list leaves that requirement out — `standing`. The entry restates whatever of the named one still holds. A name the step was not shown is refused at decode — `StepOutputFor` |
| **correction** | a complaint against a named document — it is not good enough to work from. Dies when the work that answers it lands, where a requirement stands |
| **stuck** | a step's account that it could not do the work. **Filed like any document** — what a step produced is the record; who is shown it is `visibleArtifacts`' to decide |
| **questions** | the agent asked the person something whose answer would change what it does. Not only when it is blocked |
| **finished** | the composer's answer that the work this trak was asked for is done and on the branch, so there is no plan to write. Its run lands on its own compose entry and appends nothing, which takes the trak to **`Finished`** through the same door a plan that runs out goes through. Not `failed`, which is *I cannot plan this at all* and leaves a red trak holding a worktree |
| **inherited** | the documents a child was born holding — its parent's artifacts, keyed as the parent filed them |
| **continues** | a field on a proposed step naming a document whose conversation it picks up, rather than starting a fresh one |
| **warrant** | why one gate went past with nobody reading it — the trak's **run mode**, a conflict **auto-merge** sent it back to resolve, or the **ambiguity** the turn reported and the absence of anything in the record asking for a person. `warrantFor` in `attention.ts` produces one and `applyEvent` stamps it on `Trak.marks` as the gate is taken, so a later change of mode moves none; the only account there is, since nothing writes a `HumanActed` when this happens. One of the four marks an entry can carry — the other, `Held`, is a **hold** spent there, and a map keyed by entry is what keeps a document from carrying both. On the wire as `TrakDetailDto.marks`, and drawn — as a mark on the map's row and a band inside the document it let through — only where the gate is behind and no person stood at it |

## Where a human stands

`src/workflow/domain/human-action.ts`

| | |
|---|---|
| **gate** | a state a trak is parked at with a person owing it something |
| **gate kind** | what the person is being shown: `approval`, `answers`, `checks`, `stuck`, `conversation`. The last two have **nothing to approve** |
| **`Approve`** | advance the plan. It means the same thing at every gate that offers it |
| **plan edit** | what a person changes about a proposed plan at the plan gate before taking it: `Remove`, `Reword`, `Continue`, `ClearWait`, `SwapAgent` or `PickModel`, each naming a position as proposed — and `RemovePieceStep`, `RewordPiece`, `SwapPieceAgent` or `PickPieceModel` on one step of one piece of a spawn, naming the piece and the step as proposed too. Carried as `edits` on that gate's `Approve`, never an event of its own, and laid over `Trak.plan` by `recordFacts`; the composer's `ComposerReturned` stays as it proposed. A removed entry is dropped and the unrun ones after it renumber — not a skip — and a swapped entry's key takes its new agent's name; every `continues` is re-pointed with both — `src/workflow/domain/plan-edit.ts` |
| **`Chat`** | say something — another turn of the same conversation. Answered in prose it lands back at the gate it started from; answered with an envelope on a step whose artifact stands, the envelope carries only the sections that changed, laid over the filed document, and the step goes back through its checks |
| **`Skip`** | enter the next step without the current one having filed anything. Offered only where nothing was filed |
| **`Replan`** | ask the composer what the rest of the plan should be. Offered at every step gate, and while a step's turn runs, where the route takes the drive over |
| **break out** | leave a step without waiting for it to finish, from a turn still running or from a step gate. Two presses: **file it**, which asks the step for the document it has — a `FilingAsked` event and a `Filing` turn, not a gate action — offered only where nothing has been filed, so a conversation it parked in, a question it asked or an account of why it is stuck; and **recompose**, which is `Replan` under the name the web client draws it by, offered at every step gate |
| **conversational** | an entry whose artifact is not owed on its **first** turn — the shape it must eventually file does not move |
| **ambiguity** | what a turn ran into that nobody had decided — `none`, `some`, `a_lot` — written on every artifact and every proposal about the turn just taken, never about how sure it is of the output. The one field an agent writes that opens a gate, which it is allowed to be because it can only cost a stop and because a false `none` is contradicted by the document it sits on. Required at the turn, tolerated on a stored log, where absent reads as `none` |

## A spawn

| | |
|---|---|
| **spawn** | a plan entry that is N pieces of work which do not need each other's output, each run as its own trak |
| **child** / **parent** | the trak a spawn created, and the one that created it. A child records which trak, which position, which child index, and how deep it is |
| **split** | what a child is told about the spawn it came out of: the composer's instruction for the partition, and every piece it named — a name and what that piece was asked to do, this one included. Never an id, a branch or a checkout path. In its `trak.md`, and guarded on there being another piece — `splitWithSiblings` in `src/workflow/domain/trak.ts` |
| **landing** | what a child came back with: its branch, the sha where it landed on the parent's branch, every document it filed, its requirements, and its **hand-up** where it made one. Written once, by `ChildLanded`; a child sent back after it landed and ended again comes home as a `ChildRefiled` carrying only what it filed since, which moves the parent nowhere |
| **join** | the parent bringing every landed child's work together onto its own branch |
| **hand-up** | work a child's composer judged out of every piece of the split, written on its `finished` answer. A child's alone — refused at decode on a trak with no parent — carried home in the **landing** and turned at the **join** into a **reconsult** naming the spawn position, so the parent replans. The spawn takes no gate for it; the re-cut plan takes the ordinary plan gate. One a landed child sends back after the join rides its `ChildRefiled` onto `Trak.handUps` instead, splicing nothing: the parent's next composer turn, whatever asks for it and whether it opens a session or resumes one, is shown it under *Handed up since* — `handed-up.md`, in every composer body — and the run that lands spends it |
| **hand-off** | work a composer found belonging on a base this trak does not have — a fix to code the branch already merged, a piece wanting its own pull request — written as `handOff` on either of its answers, the proposal or the finish: one description per new trak. A trak with no parent's alone — refused at decode on a child, whose branch goes back to its parent, and never mentioned to one. Each opens a trak of its own, cut from the repository's **default branch** (`Vcs.defaultBranch`, the local branch `origin/HEAD` names), born holding the description and which trak sent it (`Trak.handedOffFrom`) and nothing else, on the same **run mode**; it never comes back — no join, no merge, no wait — which is what separates it from a **spawn**. It takes the plan gate: `manual`, `smart` and `decider` stop there, `auto` does not, and a finish carrying one takes that gate where a plain finish takes none. The gate going past names the traks on the log (`HandedOff`, from the `HandOff` command in the `HandingOff` state) and the daemon opens each once — `driveHandOff` in `src/workflow/runtime.ts`. **On the trak of a goal still going nothing opens**: `HandedOff` names no trak and no base, the goal's watcher files the descriptions as `TrakHandedOff`, and the goal composer is woken to place them. Once the goal is done or dropped its trak hands off the ordinary way. `smart` goes past that gate on any goal's trak, at rest or not, since the gate cannot read the goal's log. Refused through the chat bar: the composer answering again without it has withdrawn it |
| **drop** | closing a child rather than merging it — nothing lands, and the parent is told so |

## The engine

`src/workflow/domain/decide.ts`, `replay.ts`

| | |
|---|---|
| **event** | a fact, appended to a trak's or a goal's log in the store. The log is the only durable thing; state is replayed from it |
| **`after`** | how many events a trak's or a goal's log held when the appender read it, passed on every append. A log of any other length refuses the append as `StoreConflict`, which names a second writer and is never retried where it is raised — `AppendAt` in `src/workflow/ports/store-errors.ts` |
| **lease** | a store's record of which engine copy drives a trak (`<id>`), a goal (`goal/<id>`) or runs a sweep (`job/<name>`, a **job lease**), renewed while held and free once it expires. Its record carries a turn's session and exec id for the next holder. `Leases` and `Locks` in `workflow/ports/leases.ts` and `locks.ts`; on SQLite, permits inside one process instead |
| **fence** | a lease's fencing token, passed on an append beside `after`. An adapter that checks it refuses a stale one as `StoreFenced`; the SQLite, file and memory adapters accept it and ignore it |
| **`decide(trak, event)`** | the one pure function that decides everything. No I/O, no `Effect` |
| **decision** (a `Decision`) | what `decide` returns: `Advance` (run these commands), `Await` (park) or `Settle` (nothing further on its own) |
| **command** | work the runtime does and reports back as an event — `SetupWorktree`, `Compose`, `SpawnStep`, `AskConditions`, `RunChecks`, `RunEffects`, `SpawnChildren`, `HandOff`, `JoinChildren`, `CommitWork`, `RemoveWorktree`, `MergeWork`, `StopTurn` |
| **`advance`** | the only way a trak's state changes |
| **mechanism field** | a `Trak` field that exists only because `decide` sees `(trak, event)` and nothing else. **Never crosses a boundary** |
| **at rest** | `Finished`, `Closed`, `Merged`, `Abandoned` — genuinely over, as against merely stopped. A `Finished` trak may be **waiting** on a **condition**: at rest all the same, with a step still to run when the condition is met |
| **archive** | put a trak away — the one word for it on every surface. The checkout, the branch, its recorded base and fork refs and the branch's copy on the forge are deleted, whatever is on them, in every state; the confirmation on the press is the only guard. GitHub is asked once, at the press, whether the branch's pull request merged — the answer names the ending (`Merged` with the merge commit, or `Closed`) and never changes how much is deleted. On the wire it is the `close` and `abandon` routes, which stay two: the second interrupts a drive first |
| **live** | not put away: a trak in any state but the five an archive leads through — `Closing`, `Abandoning`, `Closed`, `Merged`, `Abandoned`, which `archived` names in `domain/trak.ts`. The rest are the **archived set**, held in memory by the `Archive` port and read through `src/app/archive.ts`; a list, `ork list` and the condition sweep see the live traks and a count of the others |
| **idle** (a trak) | a **live** trak left alone: nothing drives it, it is not resting on a condition the sweep still asks, and no person's press or finished turn has landed for three days (`IDLE_AFTER_MS`, `domain/activity.ts`). Computed against the clock on every read and never recorded, so the next press or finished turn ends it with no wake press. The `Idle` port keeps each one's activity time and last list row, so the list and the condition sweep leave its log shut. Not an idle **goal** (nothing running, waiting on its person) and not a sandbox's idle stop |
| **`Failed`** | where a trak stops until a human says otherwise. Keeps its worktree, and every one is retryable. Kinds: `agent`, `provider`, `worktree`, `merge` (git declined to merge the branch into its destination — the checkout is fine), `project` (a script this project wrote could not do what it says), `engine` |
| **custody** | the record that a process is driving a trak — ephemeral, and separate from the durable log. **No longer a lock**: one daemon keeps its own drives apart with a permit, so what this is for is making an orphaned `claude` findable after a crash |
| **frame** | one append, as a watcher sees it: a log event with the state it produced, or a transcript line. `seq` is its line number in that trak's own file, so a gap is detectable. |
| **seam** | the boundary between the engine and where a trak's work runs: a local process group, or a sandbox reached through `runner.sh` |
| **seam operation** | one engine action crossing the **seam**: the sandbox's state asked first, the crossing, a transport failure (`lost`, `unreachable`) waited out on the outage's `reattach_minutes` window, and a stopped or absent sandbox read as nothing running. `crossSeam` in `src/workflow/runtime.ts`; only the **stop**'s kill goes through it so far |
| **seam status** | `SeamStatus`: what a trak's action at the **seam** is doing now — the action, its phase (`readying`, `crossing`, `waiting`), its attempt and its last error. Engine memory, never on a log; one per trak, the newest action winning, published as the `SeamStatus` frame — `src/workflow/ports/seam-status.ts` |
| **daemon** | `pnpm serve`. The one writer — every surface reads its stream and sends it requests |
| **opener** | a terminal or an editor a press opens a checkout with — a trak's from its header, the project's from the top bar — one word for both, because the engine finds, lists and remembers them the same way. Two kinds: `terminal`, a shell in the checkout, and `editor`, a window on it. Found by sweeping the machine's application folders for the claim each kind declares, picked once per machine in `openers.json` — under `~/Library/Application Support/Orkestra/` on macOS, `$XDG_CONFIG_HOME/orkestra/` or `~/.config/orkestra/` elsewhere, where nothing is found and every press is refused — and guessed where nothing is picked — `src/app/openers.ts` |
| **guard** | what stands in front of `/api/` once `ORKESTRA_PASSPHRASE` is set: a **session** cookie the login screen earns at `POST /api/session`, kept across restarts as a hash in `sessions.json` for 30 days, or the daemon's per-boot **token**, written mode 0600 into `daemon.json` for `ork` — and a third, derived from that token per trak or per goal and handed to a session's tool server, which admits that trak's or that goal's tool routes and nothing else. `/api/health` is exempt and the bundle is public; loopback is not a credential, because a tunnel connects over it. Off when no passphrase is set, and then the engine binds loopback only — `src/app/guard.ts` |

## The forge

`src/vcs/ports/forge.ts`

| | |
|---|---|
| **forge** | wherever the host repository is hosted — GitHub today, reached through `gh`. One question is asked of it: which pull request has this branch as its source — the newest, since one branch may carry several, one after another. Once one merges, later work on the branch goes into a fresh one. Written to once: the merge of a pull request — an **auto-merge** trak's, by the forge sweep, or a finished trak's, from the press on its finished band, which the forge itself accepts or refuses. Either merges by the method picked on the trak, or the repository's default |
| **auto-merge** | a trak setting beside its **run mode**, set at birth by New Trak or the goal composer's `open_trak`, and turned on or off afterwards from the run-mode picker or, at `Finished` with a pull request open, the finished band, or by a running goal set to Never or Always — `AutoMergeChanged`, refused once archived and on a child — `Trak.autoMerge`. Turning it on starts it afresh, the count at 0 and any stop cleared; turning it off ends a conflict's claim on the gates. The forge sweep merges the trak's pull request once it is `clean`, not a draft, and its checks read `passed` or `none` on the same head commit two ticks running, since a fresh push reads `none` until its CI registers, and `passed` while every check so far was skipped; a `conflicting` or `behind` one, or `failed` checks, sends the trak back to its own composer as a `Reentered` carrying a `cause`. A trak resting on a wait is merged only where the merge answers the wait — `merged`, `deployed`, or, on GitHub only, a `wait_until` on an entry that also has a `wait_for` — and a script, a `wait_until` alone or a stopped wait holds it: `mergesPastWait`. A conflict's re-entry takes every gate until the trak rests, on every mode (`Trak.resolving`, marked `Resolving`); red checks follow the mode. After `AUTO_MERGE_SENDS` sends without a merge the sweep records `AutoMergeStopped`, and a goal hears the trak as `stuck`; it stops the same way, with no send, on a pull request the forge's protection holds with green checks (`blocked`) and on `MERGE_REFUSALS` refused merges in a row. With no `origin` remote there is no forge to ask: the sweep merges the trak into the branch the project's checkout is on, as the Merge press does, waits while that checkout has uncommitted files, and sends a merge that would conflict back as a `Conflict` naming that branch. A **goal file**'s `auto_merge: never` refuses it at `open_trak` and refuses turning it on, and `always` opens every trak with it; a person changing a running goal to Never or Always turns it off or on for the goal's live traks |
| **mergeability** | what the forge would do with a pull request as it stands. Its two ways of refusing are a conflict and a branch that is behind; everything it would let through is *clean*, and *unknown* is it not having worked the answer out yet |
| **truncated** | which of a pull request's bounded lists — checks, reviews, threads, conversation — only the first page of was read. Carried so a short list is never drawn as a complete one |
